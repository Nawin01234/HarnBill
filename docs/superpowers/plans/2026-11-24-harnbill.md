# HarnBill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Live bill-splitting rooms with per-person PromptPay QR.
**Architecture:** Rust axum server owns room state; REST mutations; WS broadcasts full `RoomView`.
**Tech Stack:** Rust (axum 0.8, tokio, rusqlite, qrcode, rand, serde), Svelte 5 + Vite + TS.
**Spec:** `docs/superpowers/specs/2026-11-24-harnbill-design.md`

## Global Constraints
- All money is integer satang (i64). Percentages in basis points (700 = 7%).
- Room id 8 chars base58; tokens 24 chars.
- PromptPay AID `A000000677010111`; mobile → tag 01 `0066`+9 digits; 13-digit ID → tag 02; 15-digit → tag 03.

## Review Focus
- Price 0 / item with no claimers → excluded, warned, no division by zero.
- 3 people sharing ฿100 → 33.34/33.33/33.33, sum exactly 100.00.
- Non-admin trying to edit items/settings → 403.
- Member ticking for another member → 403.
- Invalid PromptPay ID → 400 on create, not a broken QR.

### Task 1: money.rs — `split(room: &Room) -> Breakdown` (tests: equal split remainder, shared item, discount+service+VAT order, sum == total, unclaimed excluded)
### Task 2: promptpay.rs — `crc16(&[u8]) -> u16`, `normalize_id(&str) -> Result<(u8,String)>`, `payload(id, satang) -> String`, `qr_svg(payload) -> String` (tests: CRC "123456789" = 0x29B1, phone/ID normalization, payload structure + valid CRC)
### Task 3: room.rs + db.rs + api.rs — ops with token checks; routes:
`POST /api/rooms`, `GET /api/rooms/{id}`, `PATCH /api/rooms/{id}` (admin), `POST/PATCH/DELETE /api/rooms/{id}/items[/{item}]` (admin),
`POST /api/rooms/{id}/join`, `POST /api/rooms/{id}/claim` (member, own), `POST /api/rooms/{id}/paid`, `GET /api/rooms/{id}/qr/{member}.svg`, `GET /api/invite.svg?url=`, `WS /api/rooms/{id}/live`
(tests: permission checks, claim toggle, join dedupes nickname)
### Task 4: frontend — Home (create), Room (admin edit / member tick / summary / pay sheet), invite sheet. Verify via headless screenshots at 390px + 1280px and a 3-client live test.
